# branch-visualize: --models モード（クラス図/ER 図）追加 + 非コード資産のノード除外

日付: 2026-07-15 (JST)

## 背景

branch-visualize はモデルを「1 ノード」の粒度でしか描けず、クラスの内部構造（メンバー）やテーブルのリレーションを可視化できなかった。`--models` モードとしてクラス図/ER 図を追加する。あわせて、通常モードの図にドキュメント（*.md）や CI 設定などの非コード資産がノードとして混入していた問題を修正する（ユーザー指摘）。

## 設計判断（ユーザー確認済み）

| 論点 | 決定 |
|---|---|
| 起動方法 | `--models` フラグで明示起動。クラス図 vs ER 図はモデルの出自で自動判定（コード → クラス図 / DB スキーマ → ER 図、混在は併記） |
| メンバー単位の差分表現 | 入れる（レビュー用途での本命機能） |
| 出力フォーマット | 3 フォーマット全部（mermaid / d2 / HTML） |
| 非コード資産の扱い | ノードにせず、レポートの「その他の変更」節に一覧（無言で落とさない） |

## 実装内容

- **SKILL.md**: `--models` 引数、手順 4 のノード化対象限定ルール + モデル詳細分岐、中間表現の拡張（`members` / 関係 type / `label`）、レポート雛形に「その他の変更（図の対象外）」節と凡例追記
- **format-guide.md**: 「モデル詳細図（--models）」節を新設（図種判定・共通表示規則・3 フォーマット雛形）。HTML の GRAPH JSON スキーマに `members` / `edges[].label` を追加
- **diagram-template.html**: `members` 付きノードの可変高描画（行頭記号 + 状態色、削除は取り消し線）、エッジ中点ラベル、詳細パネルのメンバー一覧、メンバー凡例の自動追記。レイアウトエンジンを可変高対応に変更（`NODE_H` 固定 → ノードごとの `h`）。`members` 無しの GRAPH JSON は従来と同一描画（後方互換）

## 実レンダリング検証で確定した仕様（重要）

すべてヘッドレス Chrome / d2 CLI 0.7.1 での実測に基づく:

1. **メンバー差分マーカーは `[+]` / `[-]` / `[*]`**。当初案の `[~]`（変更）は mermaid classDiagram のジェネリクス記号 `~` と衝突して欠落するため `[*]` に変更。全角マーカー案（＋/−/〜）は classDiagram でパースエラーになるため不採用
2. **mermaid classDiagram は `:::` + classDef でダークチップを流用可**（通常モードと同一パレット）。mermaid erDiagram はエンティティ単位の色分け非対応のため、状態は属性コメント欄マーカーで表現
3. **d2 はモデルを `shape: sql_table` に統一**。`shape: class` はダークテーマ（theme 200）でフィールド名が低コントラストになり読めない（実測）。また sql_table/class shape では `style.fill` がヘッダー背景・`style.stroke` が行背景に割り当たるため、通常ノード用 classes を流用すると行が高彩度になる。モデル図専用の `m-*` classes（ヘッダー = 状態色タント / 行 = `#141b26` 固定）+ `theme-id: 200` を採用
4. **v2.3.0 時点で未検証だった通常モードの d2 雛形も今回 CLI で検証済み**（修正不要で意図どおり）

## 検証結果

- テンプレート JS: `node --check` OK
- HTML モデル図: クラス 3 + テーブル 2 + 名前のみ関連 1・エッジラベル 5 種のサンプルで実生成し目視確認（可変高・メンバー色・取り消し線・凡例追記・エッジラベルすべて意図どおり）
- HTML 後方互換: 前回 PR の 21 ノードサンプルを新テンプレートで再生成し、スクリーンショットが前回とバイト一致（描画同一）
- format-guide の全雛形（mermaid 3 ブロック・d2 2 ブロック）を**ファイルから抽出してそのまま**レンダリング検証（出荷物と検証物が一致）

## 追補: PR 番号指定対応（同 PR 内）

使い方確認の中で「`/branch-visualize #100 --models` のように PR を対象指定したい」という要望を受け、同 PR に追加した:

- `#<数字>` トークン → GitHub MCP `pull_request_read`（method: get）で head ブランチ = 対象・base ブランチ = 比較先を解決（`--base` 明示指定が優先）
- MCP 未接続・PR 不存在はエラー終了（`--base` 省略時の open PR 自動解決と異なりフォールバックしない。明示指定の解決失敗を黙って別対象に差し替えないため）
- `#番号` とブランチ名の両方が指定された場合は AskUserQuestion で確認

## トレードオフ・補足

- mermaid erDiagram の状態色分けは表現力の限界としてレポート側の表・凡例で補完する
- HTML のメンバー行はノード幅 190px 固定のため長いシグネチャは省略表示（クリックで詳細パネルに全文）
- 「変更メンバー全件 + 未変更メンバー 8 件目安・超過は『…他 N 件』」のキャップは生成側ルール（format-guide）であり、テンプレートは渡されたものを描くだけに保つ
