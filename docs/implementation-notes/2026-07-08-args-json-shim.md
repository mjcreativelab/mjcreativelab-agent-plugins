# 2026-07-08 Workflow 雛形への args 正規化シム追加（Issue #76）

## 背景

Workflow ツールの `args` が呼び出し経路によって JSON 文字列で着弾し、雛形スクリプト内のトップレベル `args.` 参照がすべて `undefined` に化ける（開発者/QA エージェントがコンテキストを失い推測実行に陥る）。全 8 雛形の meta 直後に正規化シムを入れて恒久対処する。

## 自分で判断した事項・仕様からの調整

### 1. シム方式は「再代入方式」を採用（`$a` リネーム方式は不採用）

Issue は主案（`args = ...` 再代入）とフォールバック（`const $a = ...` + `args.` を `$a.` へ置換）の 2 案を提示し、「`args` バインディングが再代入可能かはランタイム依存のため着手時にプローブで確認」を求めていた。

着手時にエージェント起動なしのプローブ Workflow で実測:

- `typeof args` = `"string"`（JSON 文字列で着弾。症状を再現）
- `args` 再代入可能（`reassignable: true`・例外なし）、再代入後 `typeof args` = `"object"`、`args.workDir` 正常展開

再代入可能と確定したため、**主案の再代入方式**を採用した。blast radius が各雛形 1 行で済み、既存のトップレベル `args.` 参照を無改変で通せる（`$a` リネームは数十箇所の書き換えを伴い不要）。プローブ結果は Issue #76 にコメントとして記録済み。

### 2. コメント文言に Issue 番号を含めない

グローバル規約「コードコメントは履歴ではなく最終仕様のみ」に従い、シムのコメントは行の役割（`// args は文字列で届く環境があるため正規化する（トップレベルの args. 参照を機能させる防御シム）`）のみとし、Issue 番号などの履歴は入れていない。追跡情報は本ノート・コミットメッセージ・PR に残す。

### 3. CLAUDE.md の陳腐化記述を更新（Issue のやること外だが整合維持）

CLAUDE.md には「`args` が JSON 文字列で届く環境がある（#76 でシム恒久化を追跡）。恒久化までは起動スクリプト冒頭に手動で `const $a = ...` を挿入」という記述があった。本修正でシムが全雛形に恒久内蔵されたためこの記述は陳腐化する。#76 を明示追跡していた記述なので、整合維持のため「シム内蔵済み・手動挿入不要・契約は維持」に更新した（surgical・1 行）。

### 4. `docs/implementation-notes/` の過去記録は改変しない

`2026-07-07-review-prompt-sync.md` には、当時このシムを「未検証・スコープ外」として不採用にした判断が記録されている。これは当時の point-in-time 記録（アーカイブ）であり改変しない。#76 はその不採用判断に対する follow-up（プローブで検証したうえで採用）という位置づけ。

## トレードオフ

- 再代入方式 vs `$a` リネーム方式: 再代入方式は blast radius 最小（採用）。`$a` 方式は再代入不可なランタイムでも動く堅牢性があるが、今回のプローブで再代入可能を確認できたため過剰。将来別ランタイムで再代入不可が判明した場合のみ `$a` 方式へ切り替える。
