# branch-visualize

git ブランチ単位で実装内容を可視化するスキル。対象ブランチとマージ先ブランチの差分を分析し、変更モジュール・ライブラリ増減・データ/ドメインモデルと直接の関連範囲を構成図として `docs/branch-diagrams/` に出力する。

## どんなケースで使うか

- PR を出す前に、**レビュアーが全体像を掴みやすい図**を用意したい
- 作業が長引いたブランチで、**自分の変更範囲を俯瞰**し直したい
- 差分が複数モジュールにまたがり、テキストの diff だけでは関係が追いにくい

使わない場面:

- コードの指摘・品質レビュー → `/code-reviewer`
- リポジトリ全体のアーキテクチャ整理 → `/software-architect`（本スキルは変更箇所 + 直接関連範囲のみ図示する）

## 使い方

```
/branch-visualize                          # 現在のブランチ vs 自動解決した比較先
/branch-visualize feature/foo              # feature/foo vs 自動解決した比較先
/branch-visualize feature/foo --base develop
/branch-visualize --format html            # フォーマットを明示指定
```

比較先（`--base` 省略時）は「対象ブランチの open PR の base → リポジトリのデフォルトブランチ」の順で自動解決する。

## 出力フォーマットの自動選定

| 規模 | フォーマット | 特徴 |
|---|---|---|
| ノード数 ≤ 15 | Mermaid | GitHub 上でそのままレンダリングされる |
| 16〜40 or 階層が複雑 | D2 | ローカルに `d2` CLI があれば SVG も併産 |
| 40 超 | HTML | ノードクリックで詳細表示・ズーム・パン（自己完結・オフライン動作） |

`--format mermaid|d2|html` で明示指定もできる。

差分の表現は 3 フォーマット共通: 🟢 追加 / 🟡 変更 / 🔴 削除（破線枠）/ ⚪ 関連（未変更）。

## 出力ファイル

- `docs/branch-diagrams/<branch-slug>-<date>.md` — レポート本体（差分サマリ・凡例・図・ライブラリ増減・モデル一覧）
- D2 選定時: 同名の `.d2`（+ `d2` CLI があれば `.svg`）
- HTML 選定時: 同名の `.html`

生成物のコミットは行わない（ユーザーの判断に委ねる）。

## 前提条件

- git リポジトリ内で実行すること
- 比較先の PR 自動解決には GitHub MCP 接続が必要（無ければデフォルトブランチにフォールバック）
- D2 の SVG 化にはローカル `d2` CLI が必要（無ければ `.d2` ソースのみ保存）
- コード内容を外部レンダリング API に送信しない
