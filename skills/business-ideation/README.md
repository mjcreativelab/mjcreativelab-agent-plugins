# business-ideation

ビジネス・サービスのアイデアを「発散 → 深掘り → 評価」の 3 フェーズで練り上げる汎用スキル。業界・会社に依存せず、任意のテーマ（新規事業・副業・個人サービス）で使える。

[phuryn/pm-skills](https://github.com/phuryn/pm-skills)（プロダクトマネジメント全域の約 60 スキル）と near-fashion-business-ideation（特定事業ドメイン向け立案パイプライン）の両方を調査し、アイデアの質を実際に上げる装置（反証・定量化の強制・優先順位づけの規律）だけを選抜・統合して構成している。

## 特徴

- **出口で完了を定義**: 「アイデアが出た」ではなく、検証プラン表（XYZ 仮説 + 成功閾値）と Kill line（数値・期限つき撤退基準）が書けて完了
- **二層エビデンスラベル**: 数値と主張にラベルを強制し、AI が生成した想定回答・推計が実データの顔をするのを防ぐ
- **Red-team / Pre-mortem 内蔵**: 急所仮説への攻撃（steelman → Fails if 形式 → 上位 3〜5 件）と事前検死（Tigers / Paper Tigers / Elephants）で、惚れ込む前に弱点を潰す
- **差し戻しルーティング**: 評価で弱かった案を「データ不足 → 追加調査」「構造の弱さ → 深掘り・発散へ差し戻し」に振り分け、弱い案を弱いまま文書化しない
- **ドキュメント正本方式**: 検討過程を notes ファイルに育て、セッション中断・再開に対応

## 使い方

```
/business-ideation 一人暮らし高齢者向けのサービスを考えたい
/business-ideation --full 自社の物流アセットを使った新規事業
/business-ideation --quick この副業アイデアを壁打ちしたい: <アイデア>
```

| モード | 用途 |
|---|---|
| `--quick` | 軽い壁打ち。途中の装置を必須セットに絞る（出口の完了条件 — 検証プラン表・Kill line・申し送り表 — は Full と同じ。未実施の手順は成果物に「未実施」と明記される） |
| `--full` | 本気の検討。掛け合わせ発散・模倣シミュレーション含む全手順 |

引数なしで起動した場合は、Phase 0 でテーマとモードを確認する。

## フェーズ構成

1. **Phase 0 前提確認** — 意思決定アンカー・アセット・目標規模・ガードレールを固定し notes を初期化
2. **Phase 1 発散** — 3 視点発散（+ Full では掛け合わせ総当たり）→ 最低 3 案比較 → 経済性・法規制の足切りスクリーニング → ユーザー選択
3. **Phase 2 深掘り** — 問題ファースト変換 → JTBD 三層 → 課題実在性 3 点 → ビーチヘッド選定 → 価値提案 6 パーツ → 構造類型・フライホイール・KSF → Why Now → 収益モデル → 8 リスクカテゴリの仮定洗い出し
4. **Phase 3 評価** — ガードレールゲート → Red-team → Pre-mortem → 模倣シミュレーション → 整合チェック → 3 値判定 → 検証プラン表 + Kill line → 差し戻しルーティング

フェーズ境界は notes への「確定」セクション書き出しを物理ゲートにしており、後続フェーズの手順は references に分離されている（先読みによるスキップ防止）。

## 成果物

```
docs/business-ideas/<テーマスラグ>/
├── notes.md      # 検討の正本（追記で育つ）
└── summary.md    # 12 セクション固定の最終サマリ
```

## 前提条件

- 調査（実データ収集・網羅的な競合調査）はスキル範囲外。評価で「データ不足」となった論点は「追加調査すべき項目リスト」としてユーザーに引き渡す
- 法規制の判定は机上の仮判定であり、法務確認の代替にはならない（スキルは「確認済み」を自称しない）
- `AskUserQuestion` など Claude Code 固有ツールは、他エージェントでは通常の質問文にフォールバックする
