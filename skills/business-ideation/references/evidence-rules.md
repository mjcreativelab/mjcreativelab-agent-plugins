# エビデンスルール — 二層ラベル・数値台帳・証拠の等級

アイデア検討では、もっともらしい推計・創作された「顧客の声」が実データのような顔をして紛れ込む。
このルールは**何が確かめられた事実で、何がまだ仮説か**を常に区別するためのもの。全フェーズで適用する。

## 二層エビデンスラベル

### 数値ラベル（すべての数値に付ける）

| ラベル | 意味 | 書き方の例 |
|---|---|---|
| `実データ` | 自分で観測・計測した一次データ | 「登録率 8%（`実データ`: 2026-06 LP テスト）」 |
| `公開情報` | 出典を特定できる公開統計・調査・記事 | 「市場規模 1,200 億円（`公開情報`: ◯◯白書 2025）」 |
| `推計` | 前提を置いた見積もり。**前提を必ず併記** | 「月商 300 万円（`推計`: 客単価 3,000 円 × 月 1,000 件と仮定）」 |

- **ラベルなしの数値を notes / summary に書かない**
- 金額は「売上 / 粗利 / 営業利益」のどれか、「月次 / 年次」のどれかを毎回併記する（「売上 1 億」だけの表記は禁止）

### 主張ラベル（顧客・市場に関する主張に付ける）

| ラベル | 意味 |
|---|---|
| `ユーザー仮説` | ユーザー（このスキルの利用者）の考え・直感 |
| `推計` | 公開情報・類推からの推論 |
| `既存資料` | 既存の調査・記事・レポートに基づく |
| `想定インタビュー` | AI が生成した想定回答。**実証データではない** |
| `要実確認` | 実際の顧客・専門家への確認が必要と特定された論点 |

## 証拠の等級（強い順）

```
行動データ（お金・時間を実際に賭けた） > 本人の発言（実インタビュー） > 公開統計 > 類推・他社事例 > 想定・直感
```

- 「使いたいと言った」と「登録した・払った」は別の等級。検証プラン表では**行動データが取れる方法を優先**する
- `想定インタビュー` を実証扱いした瞬間に検討全体が汚染される。想定回答は「問いの精度を上げる道具」であって「裏付け」ではない

## ラベルの昇格

検証・調査で証拠が強くなったら、notes の該当箇所を**上書きせず追記で昇格**させる（例: 「WTP 月 500 円（`ユーザー仮説`）→ 2026-07 LP テストで有料登録 3%（`実データ`）」）。昇格の履歴が残っていること自体が、検討の信頼性の証明になる。

## 数値台帳

主要数値が文書のあちこちで食い違うのを防ぐため、notes 内に 1 表で集約する（書式は note-templates.md）。

- 載せる対象: 市場母数・客単価・WTP・CAC / LTV・目標規模・Kill line の閾値など、**判断に使う数値すべて**
- 同じ数値を本文で使うときは台帳の採用値を正とする。食い違いに気づいたら横断ルール 5（例外必発火）に従い停止して確認する

## ユーザー対話の言葉づかい

質問・選択肢の文面では、アルファベット略語に初出時の日本語併記を徹底する。頻出語の言い換え：

| 略語 | 併記例 |
|---|---|
| CAC | 顧客獲得コスト（CAC） |
| LTV | 顧客生涯価値（LTV） |
| WTP | 支払い意思額（WTP） |
| TAM / SAM / SOM | 市場全体の規模（TAM）/ 狙える市場（SAM）/ 実際に取れる市場（SOM） |
| KSF | 成功のカギ（KSF） |
| KPI | 測る指標（KPI） |
| JTBD | 片付けたい用事（JTBD） |
| PMF | 市場に受け入れられた状態（PMF） |
| MVP | 検証用の最小プロダクト（MVP） |
| LP | 告知用の 1 枚ページ（ランディングページ） |

notes / summary の本文は専門用語のままでよい（読み手が検討の当事者のため）。
