# Codex レビュー依頼テンプレート（実装コード）

`-codex-loop` のループ手順 1 で `codex:rescue` に渡す依頼文のテンプレート。`<>` を埋めて task として渡す。

---

## codex:rescue への依頼文テンプレート

```
あなたは GitHub Issue 対応の実装コードのレビュアーとして振る舞う。
修正価値のある欠陥のみを指摘するのが目的である。

## 入力

### 1. Issue の要件
<Issue のタイトル・要件・受け入れ基準の要約>

### 2. 実装計画（あれば）
<smart-issue-plan が作成した計画の実装手順・影響範囲の要約。計画がない場合はこのセクションを省略する>

### 3. レビュー対象（ラウンド N）
現在ブランチ <ブランチ名> の変更全体をレビューせよ。diff の基準は次の通り:

- コミット済み変更: `git diff origin/<デフォルトブランチ>...HEAD`
- 未コミット変更: `git status` / `git diff`（working tree に残っている変更も対象）

ローカル <デフォルトブランチ> は origin より古いことがあるため、必ず `origin/<デフォルトブランチ>` を基準にすること。

### 4. 前ラウンドからの変更点（2 ラウンド目以降のみ）
<採用した指摘と反映内容の要約。初回ラウンドではこのセクションを省略する>

## レビュー観点

- **仕様充足**: Issue の要件・受け入れ基準を満たしているか
- **バグ**: ロジック誤り・エッジケース・境界条件・エラーハンドリング漏れ
- **回帰リスク**: 既存の挙動・テスト・呼び出し元を壊す変更はないか
- **実装レベルの危険箇所**: インジェクション・秘密情報の混入・認可漏れ・依存脆弱性

## 制約

- 可読性・命名・スタイルの指摘は対象外（修正価値のある欠陥のみ）
- 各指摘に根拠（ファイルパス・行番号など一次情報）と重大度（High / Medium / Low）を付ける
- 指摘が 1 件もなければ「指摘なし」とだけ返す
- コードやファイルの変更は行わない（レビューのみ）

## 出力フォーマット

### コードレビュー結果（ラウンド N）

#### 指摘 1: <タイトル>
- 重大度: High|Medium|Low
- 根拠: <ファイルパス・行・確認方法>
- 内容: <何が問題か・どう直すべきか>

（以降同形式で列挙。指摘がない場合は「指摘なし」とだけ書く）
```

---

## 呼び出し時の注意

- このテンプレート全体を埋めたうえで、Skill ツールの `codex:rescue` に task として渡す
- Codex はリポジトリにアクセスできるため、diff の取得・コードの確認は Codex 側に行わせる（巨大な diff を依頼文に貼り込まない）
- Codex にコードの修正を行わせない（レビューのみ）。修正は Claude 側の妥当性判定を経てから行う
- 返ってきた指摘の再解釈・要約による弱体化をしない（妥当性判定は採用 / 不採用の分類と理由の明記のみ）
