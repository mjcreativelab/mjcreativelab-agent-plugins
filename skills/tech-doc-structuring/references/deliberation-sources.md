# 経緯素材の外部取得（Slack / Gmail / Confluence）

ADR の `## Deliberation（決定に至る経緯）` の素材（やり取りの本文）が Slack・Gmail・Confluence にあるとき、MCP コネクタ経由で取得する手順。**取得は加速手段であり必須経路ではない** — コネクタが無い環境（未接続セッション・Claude Code 以外のエージェント）では、ユーザーに素材の貼り付けを依頼する従来経路で機能は完結する。

## 前提

- 対応する MCP コネクタが接続済みであること（claude.ai コネクタの Slack / Gmail / Atlassian、または同等の MCP サーバー）
- ツール名は環境依存（例: claude.ai コネクタなら `mcp__claude_ai_Slack__*` / `mcp__claude_ai_Gmail__*` / `mcp__claude_ai_Atlassian__*`）。名前を決め打ちせず、Claude Code では ToolSearch でスキーマをロードしてから呼ぶ（例クエリ: `+slack thread` / `+gmail search` / `+confluence page`）

## 取得の規律

1. **ユーザーが指した対象だけを取得する**（URL・件名・スレッドの特定情報）。経緯を探す目的での広い横断検索・探索的検索はしない（無関係な私的情報の混入とトークン浪費を防ぐ）
2. ソース別の取得指針:

| ソース | 取得対象 | 出典の書き方 |
|---|---|---|
| Slack | permalink が指すスレッドの本文と返信 | permalink をリンクする |
| Gmail | 件名・参加者・期間で特定した 1 スレッドの本文 | 「件名 + 日付」で記す（メールの URL は他者と共有できないため） |
| Confluence | ページ本文とコメント（インラインコメント・返信を含む。コメント欄が経緯の本体であることが多い） | ページ URL をリンクする |

3. 取得できなかった場合（未接続・権限不足・見つからない）: エラー内容をそのまま報告し、素材の貼り付けを依頼する。取得できなかった部分を推測で埋めない

## 取得後の書き方

- 生ログを文書へ再録しない。`- YYYY-MM-DD 参加者: 要点と帰結` の時系列へ要約する（`NNNN-<スラグ>-deliberation.md` へ切り出す場合も同様。全文は出典リンクで辿れる状態を保つ）
- 出典は Deliberation 節の各項目の末尾（または節末にまとめて）に付す。外部 URL は frontmatter の `related` に入れない（`related` は相対パス専用）
- メール・DM 由来の内容は、実名・引用の記載可否をユーザーに確認してからリポジトリ文書に書く（公開チャンネルのスレッド・Confluence ページは通常そのまま要約してよい）
